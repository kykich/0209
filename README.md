# Утилита RTK/RTCM + DeepSeek

Веб-интерфейс для получения справки по **геодезии и RTK-поправкам** и получения
ответов от языковой модели **DeepSeek API**.

Проект — **чисто веб-версия**: встроенный HTTP-сервер Python (только
стандартная библиотека), стартовая страница `index.html` открывается в
браузере, ответ модели показывается прямо на странице. Консольная версия
(`rtk_console.py`, `service.py`, `ui.py`) удалена.

Пользователь вводит вопрос свободным текстом. Утилита через модель определяет,
по теме ли вопрос; если да — запрашивает ответ DeepSeek в выбранном формате и
показывает его на странице. Историю диалога сохраняет для продолжения между
сессиями (и между компьютерами через git).

## Возможности

- **Свободный ввод вопроса** — пользователь пишет запрос вручную.
- **Двухступенчатая отсечка темы через модель** (без списка ключевых слов):
  - ступень 1 — «классификатор» через DeepSeek решает: вопрос по геодезии
    (GEO) или про другое (OTHER:<область>);
  - ступень 2 — если GEO, продолжается диалог с выбранной ролью; если OTHER —
    вежливая рекомендация обратиться к профильному специалисту по контексту
    (например, про кулинарию — к повару). Такие «не по теме»-ходы **не
    сохраняются** в историю сессии.
- **Форматы ответа на выбор** (роль задаётся в системном промпте на каждый
  запрос, потолок длины ~100 строк/3000 знаков):
  - **Короткий** — отвечает «новичок» в геодезии (классика хорошо, GPS мало);
  - **Средний** — «техник-геодезист» (классика + GPS в общих чертах);
  - **Развёрнутый** — «специалист» (классика + RTK/GNSS + практика);
  - **Колхоз** — три мнения в одном ответе: «Повар» (слышал/видел геодезиста),
    «Геодезист» (практик) и «Архитектор» (теоретик, знает термины, но не
    практикует). Каждый высказывает своё личное мнение отдельным подразделом.
- **Корректный рендер Markdown** в выводимых ответах: `**жирный**`,
  `*курсив*`, `` `inline-код` ``, заголовки и маркированные/нумерованные списки.
- **Сохранение диалога** — история разговора с моделью хранится в
  `sessions/current.json` и продолжается между запросами; передаётся между
  компьютерами через git.
- Другие API-маршруты: сброс сессии («Новый разговор»), индикатор состояния,
  имя модели в подвале.

## Требования

- Python 3.7+
- Только стандартная библиотека (`urllib`, `json`, `re`, `os`, `http.server`) —
  **внешние зависимости не нужны**.

## Установка

Склонируйте репозиторий:

```bash
git clone https://github.com/kykich/3108.git
cd 3108
```

## Настройка API-ключа

1. Получите API-ключ на [platform.deepseek.com](https://platform.deepseek.com).
2. Создайте рядом со скриптом файл **`apidpsk.txt`** и вставьте в него ключ
   одной строкой (без лишних пробелов):

```
sk-ваш_ключ_из_deepseek
```

> ⚠️ **Важно:** файл `apidpsk.txt` добавлен в `.gitignore` и не должен
> загружаться на GitHub — это ваш секретный ключ.

## Запуск

Стартовая страница **`index.html` лежит в корне проекта**. Запуск поднимает
встроенный HTTP-сервер и автоматически открывает страницу в браузере. Если же
открыть `index.html` просто как локальный файл (двойным кликом), встроенный
сценарий страницы автоматически перенаправит вас на порт запущенного сервера,
где обслуживаются интерфейс и `/api/ask`.

```bash
python rtk_web.py
```

Либо на Windows:

```powershell
py rtk_web.py
```

Можно указать порт (и хост). При нестандартном порте страница открывается по
адресу `http://127.0.0.1:<порт>/`:

```bash
python rtk_web.py 9000           # http://127.0.0.1:9000
python rtk_web.py 9000 0.0.0.0   # доступ с других машин
```

После запуска откроется веб-страница: поле для вопроса, выбор формата ответа и
кнопка «Получить ответ». Полезные кнопки: «Новый разговор» (сбросить историю
сессии) и «Закончить» (закрыть вкладку).

## Как это работает (кратко)

1. Сервер принимает `POST /api/ask` (JSON: `question` + `format`).
2. `topic.classify_theme()` через DeepSeek решает, по геодезии ли вопрос:
   - `GEO` → продолжается диалог;
   - `OTHER` → `topic.build_redirect()` возвращает рекомендацию обратиться к
     профильному специалисту, этот ход в сессию НЕ пишется.
3. Для `GEO` в начало истории ставится системный промпт выбранного формата
   (роль или режим «Колхоз»), к нему добавляется вопрос и отправляется полная
   история в DeepSeek.
4. Ответ сохраняется в `sessions/current.json` и показывается на странице
   с рендером Markdown.

## Структура проекта

```
.
├── index.html           # стартовая страница (в корне проекта)
├── css/                 # стили
├── js/                  # клиентские скрипты (отправка вопроса, рендер ответа)
├── rtk_web.py           # веб-точка входа
├── rtk_app/             # бизнес-логика
│   ├── config.py        # пути/настройки, эндпоинт и модель
│   ├── deepseek.py      # клиент DeepSeek: роли + колхоз, chat/build_*
│   ├── topic.py         # двухступенчатая отсечка темы (GEO/OTHER + redirect)
│   ├── html_report.py   # рендер Markdown-ответа в HTML
│   ├── session.py       # сохранение диалога sessions/current.json
│   └── key_store.py     # чтение apidpsk.txt
├── web/
│   └── server.py        # ThreadingHTTPServer + JSON-API
├── sessions/            # история диалога (едет через git)
├── speech/              # протоколы разработки (едет через git)
├── apidpsk.txt          # файл с API-ключом (НЕ загружается на GitHub)
├── README.md
└── .gitignore
```

> Шифрованный файл `apidpsk.txt` (api-ключ) добавлен в `.gitignore` и не
> попадает на GitHub. Папки `sessions/` и `speech/`, наоборот, переносятся
> вместе с кодом через git.
