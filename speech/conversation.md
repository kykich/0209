 1. ЦЕЛЬ ПРОЕКТА
────────────────────────────────────────────────────────────
Утилита на Python (только стандартная библиотека) — ВЕБ-интерфейс
для получения справки по геодезии и RTK-поправкам от модели DeepSeek:

 - WEB-версия (rtk_web.py -> web/server.py):
     встроенный HTTP-сервер, страница в браузере, вопрос->ответ on-line.
   (Консольная версия и её модули rtk_console.py / service.py / ui.py
    удалены по решению пользователя — проект теперь чисто веб.)

Логика вынесена в пакет rtk_app/ (config, deepseek, topic, html_report,
key_store, session).

      колхоз система просит модель дать ТРИ мнения в одном ответе:
        Повар — слышал про геодезию / видел геодезиста, говорит поверхностно;
        Геодезист — практик с опытом, отвечает по делу;
        Архитектор — теоретик-«умник», сыплет терминами, геодезией не занимался.
      Каждый высказывает строго СВОЁ личное мнение отдельным подразделом,
      мнения не смешиваются, единого «итога» нет. Реализуется через новый
      системный промпт deepseek.build_kolhoz_system() (потолок ~150 строк /
      ~5000 знаков). В web/server.py распознаётся формат kolhoz, ставится
      этот промпт и в мете выводится «колхоз (три мнения)».
 [15] Исправлен рендер Markdown в выводимых ответах (rtk_app/html_report.py):
      стал поддерживаться inline-рендеринг:
        **жирный** / __жирный__  -> <strong>;
        *курсив* / _курсив_      -> <em>;
        `code`                   -> <code>.
      Раньше такие куски выводились «сырыми» (**...** и т.п.). Добавлена
      функция apply_inline_markdown(), вызывается после escape_html перед
      разбиением на абзацы/списки.

────────────────────────────────────────────────────────────
 4. РЕАЛИЗОВАННАЯ «ПЕРЕНОСИМАЯ СЕССИЯ ДИАЛОГА» (веб)
────────────────────────────────────────────────────────────
 Модуль:  rtk_app/session.py
 Настройка: rtk_app/config.py
   SESSION_DIR  = <root>/sessions
   SESSION_FILE = <root>/sessions/current.json

 Формат файла: список сообщений DeepSeek messages[]
   [ {"role":"system","content": <система сессии>},
     {"role":"user","content": <вопрос>},
     {"role":"assistant","content": <ответ>}, ... ]

 Функции модуля session.py:
   path()               — путь к файлу current.json
   load()               — прочитать историю (пустой список, если нет/битый)
   save(messages)       — перезаписать файл (санитизация полей)
   reset()              — удалить файл (новый разговор)
   ensure_system(...)   — гарантировать, что первая запись — system

    DeepSeek-клиент rtk_app/deepseek.py:
   chat(api_key, messages)         — отправить ПОЛНУЮ историю, вернуть ответ
   build_role_system(answer_format)— system-промпт = роль по формату
                                     (short/medium/full) + потолок длины;
                                     переменная роль применяется к КАЖДОМУ
                                     запросу (см. раздел 1..2, пункты 10-11)
   build_kolhoz_system()           — system-промпт формата «Колхоз» (три
                                     мнения: Повар/Геодезист/Архитектор),
                                     потолок ~5000 знаков (пункт 14)
   build_system(answer_format)     — алиас build_role_system (совместимость)
   build_user_message(question,fmt)- реплика пользователя (роль и длина — в
                                     системном промпте, в текст вопроса не
                                     подмешиваются напоминания)
   (прежние ask_deepseek_raw / ask_deepseek сохранены)

 Веб-маршруты web/server.py:
   POST /api/ask   — ДВЕ СТУПЕНИ: (1) classify_theme() решает GEO/OTHER;
                     OTHER -> build_redirect() даёт рекомендацию профильного
                     специалиста и НЕ сохраняется в сессию; GEO -> продолжает
                     разговор, переустановив системный промпт-роль по формату
                     на этот ход, шлёт всю историю, сохраняет assistant
                     в sessions/current.json
   POST /api/reset — очищает сессию (новый разговор)
   GET  /api/state — {exists, turns} для индикатора
   GET  /api/model — имя модели (подвал)

 ВАЖНО про перенос:
   Папка sessions/ НЕ в .gitignore -> её current.json ездит через git.
   apidpsk.txt (секрет) в .gitignore и НЕ едет. Папки answer/ и консоли
   больше нет.

  7. ТЕКУЩЕЕ СОСТОЯНИЕ НА МОМЕНТ СОХРАНЕНИЯ
────────────────────────────────────────────────────────────
 - Консольная версия удалена (rtk_console.py, service.py, ui.py) —
   проект чисто веб (rtk_web.py).
  - index.html: четыРЕ варианта ответа — Короткий/Средний/Развёрнутый/Колхоз.
 - deepseek.py: система — одна из трёх ролей (short/medium/full) + общий
   потолок ~3000 знаков; роль переустанавливается на каждый запрос. Добавлен
   отдельный системный промпт build_kolhoz_system() для формата «Колхоз»
   (три мнения Повар/Геодезист/Архитектор, потолок ~5000 знаков).
 - html_report.py: исправлен рендер inline-Markdown в ответах (**жирный**,
   *курсив*, `code`) — раньше выводилось «сырыми» звёздочками.
 - topic.py: отсечка темы без ключевых слов — классификатор через модель
   (GEO/OTHER); для OTHER рекомендация-редирект к профильному специалисту,
   такие ходы НЕ сохраняются в сессию.
 - web/server.py + js/app.js: вывод рекомендации OTHER в блоке ответа.
 - Всё компилируется (python -m compileall web rtk_app rtk_web.py проходит)
   и проходит импорт веб-модулей.
 - Smoke-тест веб-сервера: GET / =200. Живой /api/ask требует ключ+сеть.
